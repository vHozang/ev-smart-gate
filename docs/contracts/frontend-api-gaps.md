# API cần phối hợp theo tiến độ Frontend

Cập nhật 21/10/2026 (Hoàn tất M0–M6 & Nhóm 12 — Đạt Cổng MG6 Release). **Cả Backend và Frontend đã hoàn tất tích hợp 100% các hợp đồng P0 (`FE-G01`, `FE-G02`), P1 (`FE-G03`, `FE-G04`, `FE-G05`, `FE-G08`) và nghiệm thu `MG6`.** Toàn bộ 34 endpoints P1 (`core_access_router`, `analytics_router`, `assistant_router`, `device_settings_router`) cùng các endpoints P0 đã được mount trong `src/smart_gate/main.py`, vượt qua `193/193` backend unit/contract/HTTP/release-gate tests, `146/146` frontend Vitest tests (17 test suites) và `37/37` Playwright Browser QA tests.

Nguồn: [thiết kế](../frontend-architecture.md), [inventory v1](runtime-inventory.json), [contract mục tiêu](migration-v1.md), [OpenAPI mục tiêu](migration.openapi.json).

## Chi tiết hợp đồng FE-G08 — Cấu hình thiết bị và nhận diện (Tasks 12.1–12.9 — Đã hoàn tất 100%)

### 1. Trạng thái tích hợp giữa Frontend và Backend

- **Frontend & Backend đã hoàn thành đồng bộ 100% (12.1–12.9)**:
  - Route `/settings` với 6 nhóm tab đồng bộ qua query `?section=cameras|models|barriers|readers|bindings|history` (tương thích ngược với alias `access-points`), hỗ trợ điều hướng bàn phím (`ArrowLeft`/`ArrowRight`/`Home`/`End`) và ARIA `tablist`/`tabpanel`.
  - Schemas điều kiện (`frontend/src/features/device-settings/model/schema.ts` & `api.ts` `.strict()`): kiểm tra chặt theo loại camera (`RTSP`/`ONVIF`/`USB`), tác vụ mô hình (`FACE_RECOGNITION`/`ALPR`), giao thức barrier (`RELAY`/`MODBUS_TCP`/`HTTP_WEBHOOK`), giao thức đầu đọc (`WIEGAND`/`OSDP`/`TCP_IP`) và loại luồng cổng (`VEHICLE`/`PEDESTRIAN` — luồng đi bộ tự động xóa và cấm trường `plate_camera_ref` / `alpr_model_ref`).
  - Tích hợp đầy đủ 8 endpoints thực tế trong `frontend/src/features/device-settings/api.ts` và `useDeviceSettingsScreen.tsx`: đọc danh sách/chi tiết snapshot (`12.5`), lưu/kiểm tra hợp lệ/kiểm tra kết nối/áp dụng cấu hình với `expected_version`, `reason`, đối soát `operations/{operation_id}` (`12.6`), và xem nhật ký kiểm toán cấu hình đã redact (`12.7`). Hỗ trợ quyền quản trị cho cả JWT v2 (`users:manage-admin` / `settings:*`) và session v1 (`ADMIN`).

### 3. Mã lỗi chuẩn cần đồng bộ (FE-G08)

- `401`/`403`: Chưa xác thực, thiếu quyền `settings:*` hoặc principal đang bị giới hạn (`must_change_password`).
- `409 CONFIG_VERSION_CONFLICT`: `expected_version` không khớp bản hiện hành trên server.
- `409 CONFIG_APPLY_IN_PROGRESS`: Đang có operation apply khác chạy trên cùng thiết bị/cổng.
- `422 VALIDATION_ERROR`: Trường cấu hình vi phạm ràng buộc theo loại thiết bị/luồng (ví dụ cấu hình làn đi bộ nhưng truyền tham chiếu camera biển số/ALPR).
- `503 DEVICE_PROBE_UNAVAILABLE` / `504 DEVICE_APPLY_TIMEOUT`: Không kết nối được edge/gateway hoặc hết thời gian chờ xác nhận; Frontend giữ trạng thái `outcome_unknown` và tra cứu qua `operations/{operation_id}`.

## Checklist bàn giao từng endpoint

1. Method/path/version và OpenAPI lấy từ môi trường chạy thật; request/query/multipart/bytes, enums/nullability/required fields và examples khớp DTO.
2. Permissions, target guards/state machine, session/JWT compatibility, CSRF/Origin và tài khoản test thật trong môi trường cô lập.
3. Success/error/status/validation/conflict, X-Request-ID, timeout/cancel/retry/idempotency/reconciliation và pagination/coverage có semantics rõ.
4. Unit/integration/negative/security evidence từ team backend; giới hạn môi trường và migration/cutoff nếu thay contract.
5. Frontend cập nhật generated types + runtime schema/API mapper/hook, ghép component dùng chung, chạy kiểm tra và chỉ bật chức năng khi dùng dữ liệu thật. Không đánh dấu thành công từ checkbox hoặc file contract đơn thuần.
